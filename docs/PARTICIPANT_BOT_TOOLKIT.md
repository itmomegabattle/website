# Бот участников ITMO Megabattle — инструментарий и логика работы

Дата: 9 июля 2026  
Статус: рабочее ТЗ для разработки бота участников и его связки с сайтом/backend.

## 1. Роль бота

Бот участников — это персональный помощник участника Megabattle.

Он нужен, чтобы участник мог:

- быстро войти/привязать Telegram к профилю;
- открыть свою визитку;
- перейти на сайт;
- смотреть новости;
- регистрироваться на мероприятия;
- получать напоминания;
- видеть уровень, баллы, валюту;
- получать справку для перваков;
- участвовать в игровых механиках;
- получать уведомления от проекта.

Бот не должен быть отдельной базой или отдельной вселенной. Он должен быть интерфейсом к единому backend.

Целевая схема:

```text
Telegram Bot
    ↓
Backend API
    ↓
Supabase/Postgres
    ↓
Website / Mini App / Admin
```

## 2. Главный принцип

Бот участников не должен сам решать важную бизнес-логику.

Он может:

- показывать кнопки;
- принимать команды;
- отправлять уведомления;
- открывать Mini App;
- отправлять запросы в backend.

Backend должен:

- хранить профиль;
- проверять авторизацию;
- привязывать Telegram;
- проверять ITMO.ID;
- регистрировать на мероприятия;
- начислять/читать баллы;
- хранить валюту;
- управлять NFC;
- отдавать новости;
- логировать действия.

## 3. Один аккаунт: Telegram сейчас, ITMO.ID потом

Сейчас:

```text
Пользователь открывает бота
→ backend получает telegram_user_id
→ создаёт или находит профиль
→ Telegram привязывается к профилю
```

Потом:

```text
Пользователь привязывает ITMO.ID
→ backend подтягивает ИСУ/ФИО
→ ITMO.ID identity добавляется к тому же профилю
```

Итоговая модель:

```text
Один профиль Megabattle
├─ Telegram identity
└─ ITMO.ID identity
```

Важно: вход через Telegram и вход через ITMO.ID должны вести в один профиль, а не создавать два аккаунта.

## 4. Что требует ITMO.ID

До получения доступа к ITMO.ID участник может:

- создать профиль;
- открыть визитку;
- редактировать публичную инфу;
- участвовать в графе знакомств;
- смотреть новости;
- пользоваться ботом;
- смотреть мероприятия.

После появления ITMO.ID некоторые действия требуют привязки:

- официальная регистрация на мероприятие;
- отметка/check-in на мероприятии;
- подтверждение участия в официальной статистике.

Баллы могут начисляться вручную оргами и не обязаны технически требовать ITMO.ID, но для официальных автоматических начислений лучше проверять ITMO.ID.

## 5. MVP-функции бота участников

### 5.1. Старт

Команда:

```text
/start
```

Что делает:

1. Проверяет Telegram пользователя.
2. Ищет связанный профиль.
3. Если профиля нет — создаёт черновой профиль или предлагает создать.
4. Показывает главное меню.

Пример текста:

```text
Привет! Это бот ITMO Megabattle.

Я помогу открыть профиль, зарегистрироваться на мероприятия, следить за новостями и не потеряться в сезоне.
```

Кнопки:

- Мой профиль
- Мероприятия
- Новости
- Справка
- Мои баллы
- Открыть сайт

### 5.2. Привязка профиля

Сценарий:

```text
Пользователь нажал “Войти через Telegram” на сайте
→ сайт создал одноразовый код/сессию
→ перекинул пользователя в бота
→ бот получил /start link_<code>
→ backend связал Telegram с профилем
→ бот дал кнопку “Вернуться на сайт”
```

Нужен endpoint:

```text
POST /auth/telegram/link
```

Данные:

```json
{
  "linkCode": "one-time-code",
  "telegramUser": {
    "id": 123,
    "username": "nickname",
    "firstName": "Nikita",
    "lastName": "..."
  }
}
```

### 5.3. Мой профиль

Кнопка:

```text
Мой профиль
```

Показывает:

- никнейм;
- имя;
- факультет/мегафак;
- статус ITMO.ID: привязан / не привязан;
- ссылка на публичную визитку;
- кнопка редактирования на сайте;
- кнопка привязать ITMO.ID, когда будет доступно.

Кнопки:

- Открыть визитку
- Редактировать профиль
- Привязать ITMO.ID
- Мои NFC-метки

### 5.4. Открыть визитку

Бот отдаёт ссылку:

```text
https://megabattle.itmo.ru/u/:profileId
```

Или короткую ссылку:

```text
https://megabattle.itmo.ru/@nickname
```

Если будет короткий профильный route.

### 5.5. Мероприятия

Кнопка:

```text
Мероприятия
```

Показывает ближайшие мероприятия:

- название;
- дата;
- место;
- статус регистрации;
- нужна ли привязка ITMO.ID;
- кнопка регистрации;
- ссылка на страницу мероприятия.

Состояния:

- регистрация открыта;
- регистрация закрыта;
- скоро;
- мест нет;
- ты уже зарегистрирован;
- нужен ITMO.ID.

Если нужен ITMO.ID:

```text
Для регистрации на это мероприятие нужно привязать ITMO.ID.
```

Кнопки:

- Привязать ITMO.ID
- Открыть мероприятие
- Назад

### 5.6. Регистрация на мероприятие

Сценарий:

```text
Пользователь нажал “Зарегистрироваться”
→ бот отправил запрос в backend
→ backend проверил профиль
→ backend проверил ITMO.ID, если нужно
→ backend создал registration
→ бот подтвердил регистрацию
```

Endpoint:

```text
POST /events/:eventId/register
```

Ответы:

- `ok`
- `already_registered`
- `registration_closed`
- `itmo_id_required`
- `capacity_full`
- `profile_banned`

### 5.7. Check-in / отметка на мероприятии

Пока не обязательно в MVP, но нужно заложить.

Варианты:

1. QR-код на мероприятии.
2. NFC-точка.
3. Кодовое слово.
4. Админ отмечает вручную.

Для официальной отметки нужен ITMO.ID.

Endpoint:

```text
POST /events/:eventId/check-in
```

### 5.8. Новости

Кнопка:

```text
Новости
```

Показывает:

- последние новости;
- важные анонсы;
- новости сезона;
- ссылки на сайт/соцсети.

Нужно:

- новости хранить в backend/БД;
- у новостей должен быть статус `draft/published`;
- возможно сегменты: все, факультет, участники мероприятия.

### 5.9. Справка для перваков

Кнопка:

```text
Справка
```

Категории:

- Что такое Megabattle?
- Мегафаки и факультеты
- Мероприятия
- Отборы
- Контакты
- Правила
- Баллы и уровни
- NFC и визитки

Справка должна быть редактируемой из админки позже, а не зашитой в код.

Минимальная структура:

```text
FAQ category
  question
  answer
  sort_order
```

### 5.10. Баллы и уровни

Кнопка:

```text
Мои баллы
```

Показывает:

- текущие баллы/XP;
- уровень;
- сколько осталось до следующего уровня;
- последние начисления;
- место в рейтинге, если нужно.

Уровней планируется от 3 до 7.

Баллы/XP начисляются:

- вручную оргами;
- автоматически позже за некоторые действия.

История начислений обязательна.

### 5.11. Внутренняя валюта

Валюта может появиться не в первом MVP.

Будущие функции:

- баланс;
- переводы;
- одноразовые коды;
- начисления за активности;
- траты на бонусы/мерч/вайб.

Важно: валюта и XP могут быть разными сущностями.

### 5.12. NFC

В боте можно показать:

- мои метки;
- привязанные типы: брелок, карта, removable, стикер;
- ссылка на визитку;
- инструкция “как использовать метку”.

Привязка метки может оставаться на сайте, но бот может открывать нужную страницу.

### 5.13. Граф знакомств

В боте:

- короткая справка;
- ссылка на граф на сайте;
- возможно “мои знакомства”.

Добавление знакомства лучше делать через сайт/NFC, а бот только показывает состояние.

### 5.14. Уведомления

Бот отправляет:

- анонсы;
- напоминания о мероприятиях;
- подтверждение регистрации;
- напоминание перед мероприятием;
- результат модерации истории;
- начисление баллов;
- важные новости сезона.

Нужно дать пользователю настройки:

- все уведомления;
- только важные;
- отключить неважные.

## 7. Команды

Минимум:

```text
/start
/profile
/events
/news
/help
/scores
/site
```

Админские команды в боте участников лучше не плодить. Если орг заходит в бот участников, ему можно показать дополнительную кнопку “Админ”, но полноценную орг-логику держим в боте оргов.

## 8. Mini App участника

Mini App участника можно делать позже, но нужно заложить.

Что может быть в Mini App:

- профиль;
- мероприятия;
- регистрация;
- баллы/уровень;
- NFC;
- граф знакомств;
- временные фото;
- настройки уведомлений.

На первом этапе можно обойтись без Mini App участника, если сайт хорошо открывается из Telegram.

Но для лучшего UX позже Mini App нужен.

## 11. Telegram identity

Нужно хранить:

```text
telegram_accounts:
  id
  profile_id
  telegram_user_id
  username
  first_name
  last_name
  language_code
  photo_url
  linked_at
  last_seen_at
```

Ограничения:

- один Telegram user id — один профиль;
- один профиль может иметь один основной Telegram;
- перепривязка только через подтверждение или админа.

## 12. Сценарий “вход через бота”

Лучший UX для вашей экосистемы:

```text
Сайт: “Войти через Telegram”
→ сайт создаёт одноразовый link code
→ открывает бота участников
→ пользователь жмёт “Подтвердить”
→ backend связывает Telegram с профилем
→ бот даёт кнопку “Вернуться на сайт”
→ сайт видит активную сессию
```

Почему так лучше:

- не нужен лишний Telegram Login Widget;
- пользователь сразу попадает в бота;
- бот становится частью онбординга;
- удобно для NFC/мероприятий/уведомлений.

## 13. Сценарий первого запуска

Если пользователь новый:

```text
/start
→ бот создаёт профиль с Telegram identity
→ спрашивает никнейм или предлагает перейти на сайт
→ показывает главное меню
```

Минимально можно создать профиль автоматически:

```text
nickname = telegram username или first_name
telegram_user_id = Telegram id
```

Потом пользователь редактирует профиль на сайте.

## 14. Сценарий с ITMO.ID позже

Когда ITMO.ID станет доступен:

```text
Пользователь открывает профиль
→ видит “ITMO.ID не привязан”
→ жмёт “Привязать ITMO.ID”
→ проходит ITMO.ID
→ backend сохраняет ИСУ/ФИО
→ профиль становится подтверждённым
```

После этого:

- можно регистрироваться на официальные мероприятия;
- можно отмечаться;
- ИСУ подтягивается из ITMO.ID;
- ручное поле ИСУ в профиле остаётся необязательным/неофициальным.

## 15. Админские возможности, связанные с ботом

На сайте в админке позже нужны:

- список Telegram-linked пользователей;
- кто привязал ITMO.ID;
- отправить тестовое уведомление;
- массовая рассылка;
- история bot events;
- ошибки доставки;
- настройки уведомлений;
- поиск пользователя по Telegram username/id;
- ручная перепривязка Telegram при проблемах.

## 16. Логирование

Логировать:

- `/start`;

- отвязку Telegram;

- регистрацию на мероприятие;
- ошибку регистрации;
- check-in;
- начисление/просмотр баллов;
- открытие справки;

Таблица:

```text

  id

  profile_id

```

## 17. Безопасность

Нужно:

- хранить bot token только в backend env;
- не коммитить токены;
- проверять Telegram initData через HMAC;
- использовать одноразовые link codes;
- link code должен жить 5–10 минут;
- rate limit на `/start` linking;
- не отдавать приватные данные без авторизации;
- не разрешать одному Telegram привязаться к нескольким профилям.

## 18. Что не делаем в первом MVP

Можно отложить:

- полноценную валюту;
- магазин бонусов;
- Mini App участника;
- временные фото;
- сложные настройки уведомлений;
- автоматическое начисление всех баллов;
- полный FAQ-редактор;
- сложную аналитику.

## 19. MVP-версия бота

Минимально полезный бот:

1. `/start`
2. привязка Telegram к профилю;
3. главное меню;
4. “Мой профиль”;
5. “Открыть сайт”;
6. “Мероприятия”;
7. “Новости”;
8. “Справка”;
9. “Мои баллы”;
10. уведомления о мероприятиях.

Этого достаточно, чтобы бот стал частью продукта, а не просто заглушкой.

## 20. Что нужно от разработчиков бота

Для интеграции нужны:

- username бота;
- BotFather token;
- текущая структура проекта;
- как сейчас обрабатываются команды;
- используется ли polling или webhook;
- как устроена Mini App, если есть;
- какие env нужны;
- где бот будет деплоиться;
- как они хотят получать данные: REST API или SDK/package.

## 21. Рекомендация по реализации

Так как бот оргов уже пишется на TypeScript, бот участников тоже лучше делать на TypeScript.

Рекомендуемый подход:

```text
backend/
  modules/telegram/

bots/
  participant-bot/
  org-bot/

packages/
  contracts/
```

На первом этапе можно держать бота отдельно, но вся важная логика должна идти через backend API.

Позже bot handlers можно перенести в единый backend или оставить бот тонким клиентом.

Главное: данные, роли, баллы, регистрации и профили должны быть общими.

Бот участников — это не просто уведомлялка.

Это:

- вход через Telegram;
- персональная точка контакта;
- быстрый доступ к профилю;
- мероприятия;
- справка;
- новости;
- баллы;
- будущая валюта;
